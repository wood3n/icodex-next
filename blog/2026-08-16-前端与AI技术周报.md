### Cursor Cloud Agent Builds

> 参考来源：[Cloud Agents Start 3x Faster with Builds](https://cursor.com/changelog/08-13-26)

8 月 13 日，Cursor 为 Cloud Agents 推出 Builds：后台定期创建已克隆仓库、安装依赖并执行 install command 的环境副本，Agent 启动时直接复用；官方数据显示环境启动提速 10 倍、首 token 时间缩短 3 倍，且构建失败时继续使用上一个成功版本。

新环境默认启用 Builds，存量环境需在 dashboard 手动开启，也可通过 Builds tab 检查日志、commit SHA 与运行所用版本。使用 Cloud Agents 的团队应先通过 setup agent 验证安装脚本和缓存边界，再为存量环境启用，环境一致性风险为中，建议 **verify**。

## 构建工具

### pnpm 12 RC

> 参考来源：[What's different in pnpm 12](https://pnpm.io/blog/whats-different-in-pnpm-12)

8 月 10 日，pnpm 官方博客发布 pnpm 12（Rust 重写版）的差异说明，确认其处于 RC 阶段并兼容 pnpm 11 的命令、设置与锁文件格式。三处实质变化：全局命令遵循项目锁定版本（`globalShims`）、Git 依赖一律解析为规范 HTTPS URL（锁文件不再记录 SSH 地址）、移除 `--resolution-only` 标志（改用 `pnpm peers check`）。

旧锁文件中记录 SSH 地址的 Git 依赖需 `pnpm update <pkg>` 重新解析；CI 脚本若使用 `--resolution-only` 将直接报 `unexpected argument` 失败。使用 pnpm 11 的团队应先 grep 替换该标志再评估 RC，迁移风险为中，建议 **verify**。

### SWC 1.16.0

> 参考来源：[SWC 1.16.0 changelog](https://raw.githubusercontent.com/swc-project/swc/refs/heads/main/CHANGELOG.md)

8 月 14 日发布的 SWC 1.16.0 修复 JSX surrogate entity panic、静态字段参数中的 `this`、minifier 初始化循环与 React Compiler 类型重载丢失；同时调整 `Switch.body_ctxt`、拆分 TypeScript `this` 参数，并引入 `FunctionBody` 等多项 AST 破坏性变更。

直接使用 `swc_core` AST、visitor 或插件 ABI 的工具需同步修改节点匹配和序列化逻辑；仅通过上层构建工具使用 SWC 的项目仍应回归 JSX、压缩与 React Compiler 产物。AST 集成用户应先完成适配再升级，兼容性风险为高，建议 **migrate**。

### Rspack 2.1.9 与 2.1.10

> 参考来源：[Rspack 2.1.9](https://github.com/web-infra-dev/rspack/releases/tag/v2.1.9)、[Rspack 2.1.10](https://github.com/web-infra-dev/rspack/releases/tag/v2.1.10)

8 月 11 日的 Rspack 2.1.9 新增未知 `import.meta` 属性告警、`import.meta.glob` 的 `caseSensitive` 选项、Linux ppc64/s390x 构建与 `create-rspack --no-git`，并优化 copy 插件缓存与 HMR 增量处理；8 月 13 日的 2.1.10 移除了 2.1.9 中过噪的 import.meta 告警，引入新缓存系统与 `ExternalModule` 的 `chunkCondition` 钩子。

2.1.10 还将 rkyv 升至 0.8.18 修复 RUSTSEC-2026-0233/0234/0235。2.1.9 的告警在自定义运行时属性场景会大量刷屏，已随 2.1.10 撤销；新缓存系统可能改变磁盘缓存行为。使用持久缓存或依赖缓存插件的团队应直接升级到 2.1.10 并复测缓存命中，缓存风险为中，建议 **upgrade**。

### Rolldown 1.2.4

> 参考来源：[Rolldown 1.2.4](https://github.com/rolldown/rolldown/releases/tag/v1.2.4)

8 月 12 日发布的 Rolldown 1.2.4 放宽了已加载合并场景下的 namespace 提取，修复 Android arm64 上的 illegal instruction 崩溃、负向 `sideEffects` glob 保留模块，以及 devtools 日志路径未按构建目录解析的问题；同批测试补充了真实浏览器与 WebContainer 的 WASI 冒烟验证。

Android arm64 崩溃影响移动端构建场景，其余为边界修复。采用 Rolldown 原生或 WASI 绑定的工具链应升级后复测产物与日志路径，兼容性风险为低，建议 **upgrade**。

## 代码质量与组件

### Ant Design 6.6.0

> 参考来源：[Ant Design 6.6.0](https://github.com/ant-design/ant-design/releases/tag/6.6.0)

8 月 10 日发布的 Ant Design 6.6.0 新增 Listy 高性能虚拟化列表组件（支持分组、sticky headers 与命令式滚动），ConfigProvider 新增 `focusOutline` 主题 token、Input 全局 `variant` 与 Tooltip 系 `mouseEnterDelay`/`mouseLeaveDelay` 配置。

Tree 新增 `useTree` 与 `scrollTo({ autoExpand: true })`，FloatButton.BackTop 新增 `showProgress`，Table 新增 `expandable.forceRender`。

该版本同时修复了 ConfigProvider 与组件级 `style`/`styles` 混用时的语义优先级、Button loading 布局偏移、Carousel 动态子项跳回首张等问题，并为 20 余个组件补充 `nativeElement` ref 与缺失的 Props/Ref 类型导出。使用组合样式或长列表场景的团队应覆盖回归后升级，样式与交互风险为中，建议 **upgrade**。

### VoidZero 7 月回顾、Oxlint 1.78.0 与 Oxfmt 0.63.0

> 参考来源：[Tales from the Void: July 2026 Recap](https://voidzero.dev/posts/whats-new-jul-2026)、[Oxc apps v1.78.0](https://github.com/oxc-project/oxc/releases/tag/apps_v1.78.0)

8 月 12 日的 VoidZero 月报确认 Oxlint type-aware linting 已稳定，在 VSCode 等大型仓库上比 ESLint + typescript-eslint 最多快 18 倍；Rolldown 峰值内存下降约 21%，Angular CLI 默认 chunk 优化器已切换为 Rolldown，ViteConf 将于 10 月 15 日线上举行。

8 月 10 日的 Oxlint 1.78.0 与 Oxfmt 0.63.0 包含 `ClassHeritage` 分组、`TSInterfaceHeritage::expression` 收窄等 4 项 AST 破坏性变更，并新增 jsdoc `no-blank-blocks`、eslint `one-var` 规则。依赖 oxc parser/transform 的插件应先适配 AST 并比对 lint 结果，工具链集成风险为中，建议 **migrate**。

### Shadcn/UI：HITL 模拟与 Questionnaire

> 参考来源：[shadcn/ui changelog](https://ui.shadcn.com/docs/changelog)

8 月，shadcn/ui 发布两项更新：`@shadcn/helpers` 可为 AI SDK 模拟 human-in-the-loop 流程（脚本化对话可在真实 `useChat` 生命周期中暂停等待用户输入与审批）；同时新增 Questionnaire 组件，用于多步提问流（Agent 澄清、引导、问卷与配置场景），覆盖 Base UI、React Aria 与 Radix 的八种样式。

HITL 模拟面向 AI Agent 工具卡片与审批提示的测试场景，Questionnaire 为纯新增组件。使用 AI SDK 构建 Agent 界面或需要多步表单的团队可升级后验证生命周期与样式覆盖，兼容性风险为低，建议 **upgrade**。

## 运行时与桌面

### Electron 43.4.0 / 42.9.0 / 41.10.5

> 参考来源：[Electron 43.4.0](https://releases.electronjs.org/release/v43.4.0)、[Electron 42.9.0](https://releases.electronjs.org/release/v42.9.0)、[Electron 41.10.5](https://releases.electronjs.org/release/v41.10.5)

8 月 11–12 日，Electron 为 43/42/41 三个稳定分支同步发布补丁：新增 `webFrameMain.printToPDF()` 支持从主进程将单个 frame 打印为 PDF，修复 `getDisplayMedia({ audio: { restrictOwnAudio: true } })` 在 `setDisplayMediaRequestHandler` 中被忽略、Windows 注销/关机时浏览器进程崩溃，以及 Squirrel.Mac 安装器路径解析不一致等问题。

该批版本还回移植了上游 Chromium/V8 修复。维护多个 Electron 分支或依赖屏幕捕获、PDF 打印的桌面应用应升级对应分支并复测这些路径；41.x 已接近支持周期尾声，建议规划迁移。桌面运行风险为中，建议 **upgrade**。
