## 运行时与供应链

### pnpm 11.20.0

> 参考来源：[pnpm 11.20](https://pnpm.io/blog/releases/11.20)

8 月 3 日发布的 pnpm 11.20.0 修复了 11.1.0–11.19.x 在命名 registry 安装同名同版本包时，锁文件可能合并不同来源 tarball 的包替换风险。

新锁文件键会携带 `<registryName>`，下一次非 frozen 安装会重写受影响条目；团队还需保留全部已引用的 `namedRegistries` 别名，避免更新后出现 `ERR_PNPM_MISSING_NAMED_REGISTRY`。使用私有镜像、GitHub Packages 或多 registry 的项目应统一升级客户端并提交锁文件变更，供应链风险为高，建议 **upgrade**。

### Node.js 24.19.0 LTS、26.6.0 与 26.7.0 Current

> 参考来源：[v24.19.0](https://nodejs.org/en/blog/release/v24.19.0)、[v26.6.0](https://nodejs.org/en/blog/release/v26.6.0)、[v26.7.0](https://nodejs.org/en/blog/release/v26.7.0)

8 月 3 日 Node.js 发布 24.19.0 LTS 与 26.6.0 Current，8 月 5 日再发布 26.7.0 Current；LTS 补充 `blob.textStream`、稳定的 `stream.compose`，Current 增加 Perfetto 支持、NSS 根证书和模块钩子释放能力。

测试工具也获得 `context.log()`、覆盖率全量包含等改进，适合排查 CI 与运行时问题；24.x 服务可优先评估兼容性，26.x 使用者应以 26.7.0 为基线重新跑测试和诊断链路，运行时风险为中，建议 **upgrade**。

## 构建工具

### Rspack 2.1.8

> 参考来源：[Rspack 2.1.8](https://github.com/web-infra-dev/rspack/releases/tag/v2.1.8)

8 月 4 日的 Rspack 2.1.8 新增 `cache.name` 与 `cache.storage.location`，并将 `cache.storage.directory` 定义为缓存根目录，最终路径默认拼接为 `<directory>/<cache.name>`，以对齐 webpack 的持久缓存语义。

此前把 `storage.directory` 当作精确缓存路径的项目，升级后会得到额外一层目录，旧缓存也不会自动迁移；版本同时让 HMR 热清单携带更精确的 CSS 变更信息。配置了自定义磁盘缓存的构建团队需调整目录字段并清理旧缓存后做冷、热构建对比，缓存命中风险为中，建议 **migrate**。

### Vite 8.2.1

> 参考来源：[Vite 8.2.1 changelog](https://github.com/vitejs/vite/blob/main/packages/vite/CHANGELOG.md#821-2026-08-06)

8 月 6 日发布的 Vite 8.2.1 修复了 `sharedPlugins: true` 时客户端 chunk import map 失效、bundled dev 中客户端脚本插入顺序不正确，以及 CSS 压缩重复执行 Lightning CSS visitor 等问题。

该补丁还避免解析 library entry 时修改用户配置，并改进随机端口与纯 CSS chunk 的处理。使用共享插件、多入口懒加载或嵌入式开发服务器的项目可直接替换补丁版本，再复测生产构建与动态导入，构建回归风险为低，建议 **upgrade**。

### Rolldown 1.2.2 与 1.2.3

> 参考来源：[Rolldown 1.2.2](https://github.com/rolldown/rolldown/releases/tag/v1.2.2)、[Rolldown 1.2.3](https://github.com/rolldown/rolldown/releases/tag/v1.2.3)

8 月 3 日的 1.2.2 支持在动态入口中内联共享依赖，并让插件时间统计覆盖用户回调；8 月 5 日的 1.2.3 修复了 watch 批次注册失败、已废弃的 `watch.notify` 暴露及部分收尾阶段内存分配。

动态 import 较多的应用可能因此改变 chunk 组成和产物体积，依赖自定义插件或 watch API 的工具链也应检查行为差异。采用 Rolldown 原生构建或通过上层工具接入的团队应更新后核对 chunk 图、热更新与插件钩子，兼容性风险为中，建议 **upgrade**。

## 代码质量与组件

### Oxlint 1.77.0 与 Oxfmt 0.62.0

> 参考来源：[Oxc apps v1.77.0](https://github.com/oxc-project/oxc/releases/tag/apps_v1.77.0)

8 月 3 日的 Oxlint 1.77.0 增加 `file:line:column` 形式的 GitHub 注释，并改善 `.gitignore`、JavaScript 插件名和多条规则的处理；同批 Oxfmt 0.62.0 支持 Vue 中的 TSX、在 check 模式展示颜色差异，并改用新的 YAML 格式化器。

YAML 输出与已有格式化基线可能出现差异，而 CI 注释格式会影响代码扫描集成。将 Oxc 用于提交检查或格式化的项目应固定版本、比对 YAML 与 Vue 文件的变更，并确认 GitHub Actions 注释仍被正确解析，质量门禁风险为中，建议 **verify**。

### ESLint 10.8.1

> 参考来源：[ESLint v10.8.1](https://eslint.org/blog/2026/08/eslint-v10.8.1-released/)

8 月 7 日发布的 ESLint 10.8.1 修复了 `no-unused-labels` 与 `no-unused-vars` 自动修复可能触发自动分号插入的问题，也降低了 `getter-return`、`accessor-pairs`、`id-denylist` 和 `id-match` 的误报；官方同时标注 ESLint v9 已于 8 月 6 日结束维护。

仍停留在 v9 的仓库不再获得维护修复，应把升级到 v10 与本次补丁合并安排；启用相关规则的项目需先在全量代码上运行 `--fix-dry-run`，再审阅边界语句和配置兼容性。存量规则集风险为中，建议 **migrate**。

### Ant Design 6.5.4

> 参考来源：[Ant Design 6.5.4](https://github.com/ant-design/ant-design/releases/tag/6.5.4)

8 月 7 日发布的 Ant Design 6.5.4 修复了仅传 `onClose` 时 Alert 关闭按钮隐藏、`Checkbox.Group` 接收空值崩溃、Table 跨页全选错误选中禁用行、Transfer 过滤后取消全选，以及 RangePicker 未透传语义回调等问题。

该版本还改善了 FloatButton 的减少动态效果和多项图标、颜色与类型细节。使用批量表格操作、无障碍日历或动态表单选项的应用，应覆盖这些交互路径后更新依赖，组件交互风险为低，建议 **upgrade**。

## 文档解析与 AI 工具

### Firecrawl anydoc 与 pdf-inspector

> 参考来源：[anydoc](https://github.com/firecrawl/anydoc)、[pdf-inspector](https://github.com/firecrawl/pdf-inspector)

8 月 3 日，Firecrawl 公开 anydoc：这是一个纯 Rust 的文档转换库，可将 Office、OpenDocument、RTF、EPUB、CSV 和文本型 PDF 统一转换为 GitHub Flavored Markdown，并提供 Node.js、Python 与 WebAssembly 绑定；它通过同团队的 pdf-inspector 处理 PDF。

pdf-inspector 会先识别文本型、扫描型、图像型或混合 PDF，再对有文本层的页面本地提取并生成 Markdown；扫描页、加密文件和不受支持格式仍需交由 OCR 或异常处理链路。处理多格式附件、RAG 导入或 Agent 文件输入的团队，应以真实语料核对结构保真度、OCR 回退与资源限制，解析质量风险为中，建议 **verify**。

## AI 开发工具

### ChatGPT：GPT‑5.6 Sol 更新与 Free 用户 Luna 扩展

> 参考来源：[OpenAI 产品公告](https://openai.com/index/improving-gpt-5-6-sol-in-chatgpt/)

8 月 6 日，OpenAI 更新 ChatGPT：Plus 和 Pro 用户可使用更注重事实可靠性与回答聚焦度的 GPT‑5.6 Sol，并通过滑杆选择思考强度；Free 与 Go 用户的默认模型将在当周切换为 GPT‑5.6 Luna。

从下周起，Free 与 Go 用户将获得不限量文本聊天和用于较难问题的 Think 按钮，但文件上传、图像及其他工具仍保留限制并受滥用防护约束。依赖免费额度进行原型验证或客服流程的团队，应核对账号实际 rollout、工具配额与输出质量基线，可用性风险为中，建议 **verify**。

### Cursor Google Workspace Plugins

> 参考来源：[Cursor changelog](https://cursor.com/en-US/changelog)

Cursor 在 8 月 3 日公布 Google Workspace Plugins，Agent 可通过新增插件读写并执行 Gmail、Google Drive 与 Google Calendar 相关操作，插件可从 Marketplace 安装或按需定制。

这扩大了编码 Agent 可触及的企业数据和外部动作范围，也会改变既有的最小权限假设。计划接入的组织应先核对 OAuth 授权范围、数据保留策略与审批流程，并在隔离账号验证可访问资源，数据权限风险为中，建议 **verify**。

## 数据与 UI

### TanStack Table V9

> 参考来源：[Announcing TanStack Table V9](https://tanstack.com/blog/announcing-tanstack-table-v9)

8 月 4 日，TanStack Table V9 宣布稳定发布：核心改为可 tree-shake 的插件架构，采用 TanStack Store 提供响应式状态，并提供 10 个框架适配器；官方示例中，百万行八列数据的堆内存从 2.71 GB 降至 380 MB。

这是跨 API 与状态管理方式的主版本更新，实际收益取决于启用的功能和渲染层。大型数据表、服务端分页或多框架共享表格逻辑的团队，应先在独立分支完成适配器与扩展点迁移并复测内存基线，迁移风险为中，建议 **migrate**。
